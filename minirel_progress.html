30-second summary
  • The original Unix-oriented, single-user educational system now builds and runs natively on Windows.
  • MINIREL now has persisted key constraints, real NULL storage, strict type/length validation, native row updates, and five broad MCP capabilities.
  • Cooperating processes receive strict table-level serializable isolation with explicit commit and rollback.
  • Explicit transactions are protected by a checksummed physical WAL with forced commit, startup redo/undo, torn-tail handling, and recovery for create/drop.
  • The next durability step is implicit WAL-backed autocommit, followed by bounded/background checkpointing.

Concurrency and transaction design

Relation locking

Shared locks protect reads; exclusive locks protect inserts, deletes, updates, loads, schema operations, and generated result relations.

  • Files: .minirel-table-<relation>.lock
  • Windows: LockFileEx
  • POSIX: fcntl

Writer and catalog coordination

Per-table writer gates serialize lock upgrades. Catalog readers share a catalog lock while metadata and relation-count changes refresh and write under exclusive ownership.

  • .minirel-writer-<relation>.lock
  • .minirel-catalog.lock

Strict two-phase locking

Transactions retain acquired locks until commit or rollback. Readers cannot observe uncommitted writes to a locked table.

  • Serializable at table granularity
  • Five-second lock/deadlock timeout

Failure behavior

A visible command error marks the transaction failed. A later commit rolls everything back rather than preserving earlier commands.

  • closedb is rejected during an active transaction
  • quit rolls back before closing

WAL and recovery design

Physical record format

Every record includes magic, version, record length, checksum, LSN, transaction ID, previous transaction LSN, relation/page identity, type, and payload length.

Record types

BEGIN, PAGE, BACKUP, DROP, COMMIT, and ABORT. PAGE records store both 512-byte before and after images.

Write ordering

FlushPage() appends and forces WAL before writing a data/catalog page. Commit appends and forces COMMIT before returning success.

Automatic recovery

Exclusive startup recovery scans valid records, truncates a torn tail, redoes committed pages, undoes incomplete pages, resolves resource lifecycle, and checkpoints the log.

Deterministic crash boundaries covered
  • after_wal_page: crash after WAL force but before the data-page write.
  • after_data_page: crash after uncommitted data reaches the table file.
  • after_commit_log: crash after the durable commit record to prove redo.
  • after_recovery_page: crash during page replay to prove repeatable recovery.
  • after_recovery_resource: second crash while restoring create/drop resources.
  • Torn WAL-tail, incomplete create, incomplete drop, committed drop, and backup cleanup ordering.
Native update command behavior 
update students set name = "Grace Hopper", score = 99.5
where (id = 2 and score >= 80);
  • Multiple assignments and and-joined predicates.
  • Operators: =, >=, >, <=, <>, and <.
  • Exclusive locking and participation in commit/rollback.
  • Complete final-state validation before the first row is written.

Known boundaries and next milestones

Implicit autocommit WAL

Mutations outside explicit begin/commit do not yet receive the same crash guarantees.

Checkpoint management

Add WAL-size thresholds and concurrent/background checkpointing instead of checkpointing only during exclusive startup recovery.

Richer consistency

Add DEFAULT, CHECK, and FOREIGN KEY constraints on top of the completed NULL and strict-write foundation.

Native introspection

Add describe <relation> for human users; MCP discovery already exposes structured schemas.

Indexes and planning

Replace placeholder index commands with a real B+ tree or hash index, then add indexed lookup, join strategies, estimates, and explain.

Schema evolution

Implement offline fixed-record table rewrites for adding columns while preserving atomic catalog/table replacement.

Deadlock selection

Replace timeout-only handling with a wait-for graph and deliberate victim selection.

Longer recovery soak

After broader soak testing, remove the whole-file backup safety net and rely on WAL-native lifecycle recovery.
